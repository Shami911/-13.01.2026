Задание B1 — «Простой скрипт-помощник» (Bash)

Bash-скрипт clean_old_logs.sh принимает два аргумента:

Путь к директории с логами

Количество дней (N)

Находит .log файлы старше N дней (find -mtime +N)

Выводит список файлов и запрашивает подтверждение удаления (read -r -p)

При вводе y — удаляет найденные файлы, при n — завершает работу

Скрипт проверяет корректность входных данных и наличие директории

Задание B2 — «Маленькая проблема в Git» (Git)

Ситуация: незакоммиченные изменения в ветке feature/junior-task.

Решение:

Сохраняем изменения во временном хранилище: git stash push -m "Комментарий"

Переключаемся на main: git switch main

Исправляем баг, коммитим изменения

Возвращаемся в feature/junior-task: git switch feature/junior-task

Восстанавливаем сохранённые изменения: git stash apply или git stash pop

При необходимости переименовать последний коммит: git commit --amend

Задание B3 — «Объясни концепцию» (Понимание CI/CD)

Настроен CI/CD пайплайн для автоматической сборки Docker-образа при пуше в ветку main (GitLab/GitHub):

Запуск тестов — юнит-тесты, линтеры, статический анализ

Сборка Docker-образа (docker build -t my-app:latest)

Пуш образа в Docker Hub (docker push)

Уведомление в Telegram о результате пайплайна (успех/ошибка)

Объяснены ключевые моменты:

Runner выполняет job в изолированной среде (Docker executor)

Secrets для токенов и учетных данных должны храниться отдельно

Артефакты передают данные между job

Тесты работают как gate: если они не проходят, сборка и публикация образа не выполняются

Docker-образы можно тегировать latest или хешем коммита для отслеживания версий
